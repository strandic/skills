# plan <ticket>

1. Read the ticket, its named files, the house rules and the lessons since the last retro marker — a lesson whose class matches the change is a spike input. Triage. Refreshing an old brief: nothing is inherited. **Research** before the spike: list every outside thing the change calls, parses or emits — dependencies, formats, protocols, the platform — with the command that listed it. A read-only lane returns, per item: its docs and installed source at the pinned version, the governing spec section, the enumerations spike q2 needs, known hazard classes of constructs the change adds, for any design choice the alternatives prior art (papers, shipped products, practice) shows, the current version of each dependency it touches and, for a version change, the diff of every changed dependency's default limits, timeouts and flags, transitive ones included, between the two pins — each a §2 Sources row — plus the queries that found nothing. A source is a spike input, never a reading: it becomes a Partition row or an attack line; only execution holds a claim. A §3 line or gate resting on an `unsourced` claim is a question or a DEFAULT marked `unsourced`.
2. **Spike before you freeze.** Read [spike.md](spike.md); execute every sketch, in a throwaway worktree per house rules. Run the suite with the sketch and every new fixture in: what breaks goes in "Existing tests that change", each flipped expectation a ruling; a skipped test naming a changed symbol runs with its resource or reads `NOT RUN (why)`. Run the changed tests with the sketch out and the table's edits in: that failing list plus the §4 reds is the predicted red set. Put each claim through spike.md's five questions and the hostile corpus. Then write §7's **attack lines** and launch the **attack lane** (patches from scratch, tree unchanged): it executes every line and re-reads every source, returning raw values against the named oracle or `NOT RUN (why)` naming the missing resource; you grade. A reading that changes a sketch sends the changed lines back through the five questions and the lane.
3. **A finding stops the plan** only when it (a) contradicts or falls outside a ruling or the ticket's stated design; (b) makes a gate rule ambiguous, unevaluable, or FAIL with the intended fix in; (c) shows wrong output — output that tells its reader something false, however harmless — or a forbidden state reachable through the change, including a value the system writes that its own input validation would refuse; you never accept wrong output or a forbidden state; a ruling accepting one shape does not cover a new one: change the sketch until the probe passes, or ask — wrong output judged unreachable is a DEFAULT in the plan's ending, its reading beside it; (d) shows an impact the ticket did not weigh: data loss, cannot start, unavailable to others, a leak, silently wrong results. Everything else goes in §2's What the planner saw. A pre-existing bug is proposed as a new ticket; folding it in is a ruling.
4. **Ending: questions.** Finish the spike first, then ask. More than three questions in one round means not settled: back to the design interview. Note on the ticket "Plan paused: <n> questions" with the readings; commit per house rules, stop. The answers go verbatim onto the ticket's rulings — an explicit answer, "go with reco" included, is a ruling; only silence on a DEFAULT is a default; re-spike on the ruled design and continue.
5. **Ending: brief.** Write it from [brief-template.md](brief-template.md), every section. Every gate rule is **written before the first run**: a counted threshold is `FLOOR = measured − margin` (default margin 2 cases); an invariant has no floor. A brief is frozen only when every §7 attack line and Sources row has its reading in §2 or a `NOT RUN (why)` — every such `NOT RUN` also in the review lane's cell — and every Partition row its line's reading; §7's lane cells are [lanes.md](lanes.md) text with ids filled; a grep of §3, the sketches' comments, the doc comments of the files it names and the lane cells finds no class word without a line id; every §4 red assertion is the executed text; every §5 rule has the template's fields, and one with no FAIL reading is deleted and its binding test listed. Every plan ending — brief, trivial, questions — ends with `unruled: <one item> — default <x>` or `unruled: none`. Note on the ticket and commit per house rules; stop.
