# retro

On `retro`, run [retro-workflow.js](retro-workflow.js); the human decides; the record goes in the retros folder. Each lesson and open item since the last marker is adopted into the method or the house rules, or dropped. A lesson dropped as covered quotes the covering sentence and walks its own case through it; a recurrence re-adopts it. A pre-registered measure names the class that counts, an impact floor, the paths it covers, the committed artifact (one the measured process does not write) and the command that counts it, and its reading on the runs in hand before it is frozen; other counts, disclosed beside it, never decide; its consequence is honoured as written. This skill changes only at a retro, in words a stranger's repo could use: a new rule names the class of failure it prevents, never the case that prompted it. The retro reports tokens per load path (plan at the brief ending, plan at the questions ending, run, retro) before and after, by the skill repo's `scripts/size_paths` command; no load path grows unless the human rules it; the trap bank, not the count, decides each cut. Before adoption, each script the retro adds or changes passes the skill repo's lint and tests. Each checker runs over every brief, trivial note and PR body merged since the last two markers, in repos whose house rules allow a retro to read them; each refusal of a record the method allows becomes a red test, and the draft fixes it or narrows its scope. The id grammar the method mints is written once, in check_pr.py's docstring, and tested by one case per form found on disk. Beside the pre-registered escape measure, the retro counts tickets whose fixing diff touches a file the last retro shipped, and attributes escapes by `git blame` of the fixed lines, not by the ticket's text; beside the share of recommendations followed, it reads rulings reversed within 7 days.
