One ticket → one **brief** → one **run** → one PR. The brief is the whole contract: an agent that has read only it and the files it names can do its part. **Invoking `run` is the go.** The human's checkpoints are the design interview, rulings and `run` — never the PR: a decision "left for the PR" is one you made alone. A number, SHA or count written anywhere (ticket, comment, brief, PR) is pasted beside its command or marked `unexecuted`.

## House rules

Before any branch, read the repo's `docs/plans/README.md` if it exists: every mechanic this skill leaves to "house rules". This skill says *what*; that file says *how* in this repo — cite its commands, never restate them. Defaults when there is none, on the base branch: brief `docs/plans/<date>-<ticket>-<name>/plan.md`, lessons `docs/plans/lessons.md`, retros `docs/retros/<date>-<topic>/`.

## Asking the human

One format, in prose, free-text answers welcome: the reading · the mechanism · which side is wrong — the rule, the ticket or the code · the options, one-line consequence and executed reading (or `unexecuted`) each, recommendation first · where the residue goes. A **RULING** changes a numbered ruling, a ruled residue, a frozen line, a gate, a lesson the plan cites, or accepts a shape plan step 3(c) names; it quotes what it touches and waits for an answer. Anything else is a **DEFAULT**: the recommendation stands unless struck; `go` or silence accepts it; a struck DEFAULT becomes a RULING. A DEFAULT may add a test, never flip one. For a pre-registered threshold, recommend a reading; never draft the replacement number before the ruling.

## Triage

- **Trivial** — judged by reading (a check that changes nothing tracked may narrow the fix; its command, reading and input alphabet (spike.md q2) go in the note): the ticket names the change, it fits one small diff with one test or command that reads red on the base (say how), and its worst case, following the changed error paths, is an inconvenience — never a plan-step-3 (c)/(d) class, its own checks' readings included. An ADR or decision record is never trivial. Anything beyond the ticket's words is a one-line question, never folded in. The note on the ticket, per house rules: the sites · the red check · the worst case · a source per outside behaviour touched (plan step 1), or `no outside behaviour` with the command that listed what the diff touches · `unruled:`; stop. On the go, do it per house rules, claiming on the ticket, as in run step 6, the readings that stand in for the review wave.
- **Settled?** (i) The design is decided — measured evidence with weighed options, an ADR, or the human's rulings — AND (ii) the gate is evaluable today: it names its metric and dataset unambiguously and the data exists (no dataset? a unit test plus one executed stand-in probe). An ADR waives (i)'s evidence, never (ii); a gate observed to read two ways on executed data is not settled. Not settled ⇒ a design interview as wave −1, one open question at a time, opening with research (plan step 1); a design that follows a reference also needs two independent implementations agreeing on the inputs it decides (executed) and an aggregates-only count of the real inputs it changes (or `no real data: <why>`) — disagreement or 0 means not settled. Outcome onto the ticket; then plan. The brief never settles a design.
- **Error directions.** The design interview writes a design's two error directions and which one corrupts output; the frozen rule never errs that way.
- **Two paths only.** Every change that reaches a PR is trivial or briefed; a fix an investigation finds is a new ticket, triaged before any code. Scrapping or superseding a ticket greps for its id; each DEFAULT, residue or TICKET row resting on it reopens on its own ticket.
- **Siblings** fold into one brief and one PR only when they share a file or are not shippable apart, and never when the sibling's fix errs the corrupting way.

## plan <ticket>

1. Read the ticket, the files it names, the house rules, and the lessons since the last retro marker — a lesson whose class matches the change is a spike input, cited in §2. Triage. Refreshing an old brief: nothing is inherited. **Research** before the spike: list every outside thing the change calls, parses or emits — dependencies, formats, protocols, the platform — with the command that listed it. A read-only lane returns, per item: its docs and installed source at the pinned version, the governing spec section, the enumerations spike q2 needs, known hazard classes of constructs the change adds and, for a new design, prior art (papers, shipped products, practice) — each a URL or `path:line@version`, a verbatim quote and the brief sentence it supports — plus the queries that found nothing. A source is a spike input, never a reading: it becomes a Partition row or an attack line; only execution holds a claim. A §3 line or gate resting on an `unsourced` claim is a question or a DEFAULT marked `unsourced`.
2. **Spike before you freeze.** Read [spike.md](spike.md); execute every sketch, in a throwaway worktree per house rules. Run the suite with the sketch and every new fixture in: what breaks goes in "Existing tests that change", each flipped expectation a ruling; a skipped test naming a changed symbol runs with its resource or reads `NOT RUN (why)`. Run the changed tests with the sketch out and the table's edits in: that failing list plus the §4 reds is the predicted red set. Dry-run every gate rule with the fix in and show one reading where it FAILS. Put each claim through spike.md's five questions and the hostile corpus. Then write §7's **attack lines** and launch the **attack lane** (patches from scratch, tree unchanged): it executes every line and re-reads every source, returning raw values against the named oracle or `NOT RUN (why)` naming the missing resource; you grade. A reading that changes a sketch sends the changed lines back through the five questions and the lane; a line whose reading holds becomes a §4 test.
3. **A finding stops the plan** only when it (a) contradicts or falls outside a ruling or the ticket's stated design; (b) makes a gate rule ambiguous, unevaluable, or FAIL with the intended fix in; (c) shows wrong output — output that tells its reader something false, however harmless — or a forbidden state reachable through the change, including a value the system writes that its own input validation would refuse; you never accept either, and a ruling that accepts one shape does not cover a new one: change the sketch until the probe passes, or ask — wrong output judged unreachable is a DEFAULT in the plan's ending, its reading beside it; (d) shows an impact the ticket did not weigh: data loss, cannot start, unavailable to others, a leak, silently wrong results. Everything else is recorded in the brief as what you saw. A pre-existing bug is proposed as a new ticket; folding it in is a ruling.
4. **Ending: questions.** Finish the spike first, then ask. More than three questions in one round means not settled: back to the design interview. Note on the ticket "Plan paused: <n> questions" with the readings; commit per house rules, stop. The answers go verbatim onto the ticket's rulings — an explicit answer, "go with reco" included, is a ruling; only silence on a DEFAULT is a default; re-spike on the ruled design and continue.
5. **Ending: brief.** Write it from [brief-template.md](brief-template.md), every section. Every gate rule is **written before the first run**: a counted threshold is `FLOOR = measured − margin` (default margin 2 cases); an invariant has no floor. A brief is frozen only when every §7 attack line and Sources row has its reading in §2 or a `NOT RUN (why)` — every such `NOT RUN` also in the 3a cell — and every Partition row its line's reading; §7's lane cells are template text with ids filled; a grep of §3, the sketches' comments, the doc comments of the files it names and the lane cells finds no class word without a line id; every §4 red assertion is the executed text, its file beside the brief; every §5 rule has the template's fields, and one with no FAIL reading is deleted and its binding test listed. Every plan ending — brief, trivial, questions — ends with `unruled: <one item> — default <x>` or `unruled: none`. Note on the ticket and commit per house rules; stop.

### Wave rules (hard)

- **Executed text is committed as it ran.** The brief's executed files (tests and sketch, beside `plan.md`) and a §9 amendment's executed text are committed verbatim by the orchestrator, tests first, each commit's diff equal to its text and its subject saying so. What the brief leaves as prose goes to ONE implementer lane.
- **Tests first.** The tests commit, with its edits to existing tests, precedes any code; the orchestrator runs the house rules' file checks on it and diffs the observed red set by name against the predicted one: every *red* reaches its own assertion and fails for the stated reason (a file that cannot load is a finding; stub the new signature where the language needs one), every *guard* is green.
- **A review wave, always.** Reviewers never edit the repo: they patch from a scratch directory and give every finding a minimal runnable reproduction; the orchestrator checks the tree is otherwise unchanged. *Adversarial* when the brief's worst-impact line calls for it — attacks **executed, not reasoned** (the template's 3a row); an all-clear with no observed run does not count. *Code review* otherwise (3b).
- **Orchestrator-only** — git, ticket writes, the spike, the live-data run, the PR. Workers use no real data and no live server.

## run <ticket>

Precondition: the brief is where the house rules put plans and the ticket says awaiting go, not shelved.

1. **Wave 0.** Branch and worktree per house rules, with everything the suite needs installed; ticket → in progress.
2. **Wave 1**, per the wave rules. An implementer lane's prompt confines it to the worktree and its files, names the test, lint and file-check commands that define done, lets it read the base only through `git show`, never touch the index, and makes it report the tests failing before and after and any blocker outside its files — stop, do not fix it.
3. **Wave 2, integrate.** Full suite and lint, passed AND skipped against the base, same toolchain, each run's results in the reports folder so every failure has a name: a new skip or failure is a finding. Commit per house rules.
4. **Wave 3, review.** Label every finding APPLY, DECLINE, TICKET or RULING (a RULING row goes in the PR's Decisions table); a DECLINE adds one reason: `unreachable` · `pre-existing` · `out-of-scope` · `style` · `superseded` · `false-positive`; an executed all-clear is verification, not a row. An applied behaviour change ships regression tests built from the reviewer's reproduction — one per argument and per read, decode or parse taking the finding's kind of input — shown red on the pre-fix source; each review-round commit names its author.
5. **Stop for a RULING** whenever a change would edit a numbered ruling, a line of §3 or §8 or a line a §3 row points at, or a gate rule or command — one that read FAIL, could not run, or passed but is wrong — and for any finding in a plan-step-3 (c)/(d) class. Any other §2 amendment is a DEFAULT: red-first regression test, a §9 row marked `default`, listed in the next stop message. Record each ruling in §9 and put amended text in later lane prompts; nothing above §9 is edited after `run`, hygiene aside, and observations never go in the brief.
6. **Wave 4, gate and PR.** The live-data run on the final commit — each §5 rule by its own command line, on the tools committed there, read per its settle clause; a scratch copy, an altered flag or a second reading after a non-PASS is a RULING stop, recorded in §9 even when granted; a later code commit voids the run. PR body: a first line linking the plan ending (trivial note or brief commit) — none, no PR · tickets, brief path · **What** · **Verification** — suite and lint against the base, each §5 rule and each lane reading, taken on the PR head · two tables, written only here, each under its fixed key and dropped when empty: **Decisions** (decision · label · what was done · why), keyed "**RULING:** the ticket owner decided before the work went on. **DEFAULT:** recommended and shown to the ticket owner, and it stood because they didn't strike it."; **Findings** (finding · label · what was done · why), keyed "**APPLY:** fixed in this PR. **DECLINE:** looked at and deliberately not acted on, with the reason. **TICKET:** real, but tracked in its own ticket." Why gives the reason only; every row reads without the ticket or the brief, an id defined elsewhere only beside a link to its record · **Follow-up**. The stop message and the ticket link those tables and list every DEFAULT row and any commit after the review round, marked unreviewed. Ticket per house rules. Stop.

The human merges. Cleanup is a house rule and ends by appending any lessons; every plan ending, run stop, scrap and cleanup appends its own stats line (house rules give the format).

## retro

On `retro`, run [retro-workflow.js](retro-workflow.js); the human rules; the record goes in the retros folder. Each lesson and open item since the last marker is adopted, dropped or copied under the new marker; an open item two retros leave untried is dropped. A lesson dropped as covered quotes the covering sentence and walks its own case through it; a recurrence re-adopts it. A pre-registered measure names the class that counts, an impact floor, the paths it covers, the committed artifact (one the measured process does not write) and the command that counts it, and its reading on the runs in hand before it is frozen; other counts are disclosed beside it and never decide; its consequence is honoured as written. This skill changes only at a retro, in words a stranger's repo could use: a new rule names the class of failure it prevents, never the case that prompted it. The retro reports word counts per file before and after and cuts at least as many words as it adds, unless the human rules otherwise.
