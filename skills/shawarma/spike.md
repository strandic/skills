# The spike — read at `plan` step 2

The spike tries to break each brief claim — *this sketch does X*, *these tests break and no others* — before freezing: five questions, each answered by an artefact pasted into a named slot, never prose.

## Mechanics

- **Patch, never edit.** Load the sketch from the scratch directory through an explicit opt-in (house rules name it), never a file the tooling discovers itself. Run the unpatched control first; then prove every variant (patch, copy, mutant) was live: one check that passes with it and fails without; a batch reading all equal to the control's is a liveness failure until shown otherwise. Afterwards the tree is unchanged.
- **A stand-in is marked and seeded.** When a rule's dataset is unreachable now, dry-run on a stand-in and mark the rule `DRY-RUN ON STAND-IN — real run pending, orchestrator only`. Seed it with every Partition kind (q2) before trusting a PASS.
- **Bound every probe that can amplify.** Whenever the diff adds or changes a repeat over input — a regex quantifier, a loop over user-sized data, a recursion, a call handing user-sized input to a library: every cost probe runs in a subprocess under wall-clock and memory caps at geometric sizes, on one accepted input, one rejected only after the most work possible (a long valid prefix, the deepest nesting, the widest fan-out), and one at each limit the called code declares, each input dimension (count, bytes) grown alone and two at once. It reads CPU time — the clock named with its documented scope, process or thread — and peak memory, head against base on the same input, through the caller's entry point, with every pass it runs; a ratio to any other control is not a cost reading. The brief states the bound; FAIL is the smallest size past it. A DEFAULT that accepts a cost cites both readings. A committed cost test asserts a count of work where the code exposes one, else a ratio of sizes (4n against n, best of k, its margin beside it); its absolute timeout is a hang guard, never the claim.
- **Write what cannot be seen.** Non-printing characters and non-ASCII whitespace are `U+XXXX` in prose and escapes in code, enforced by the house rules' file check.

## Five ways a brief lies

1. **Unrun.** *Did this exact thing execute, in full?* A sketch, a rule, a metric definition, an inherited test — each counts as executed only if its literal body ran, every assertion included. **Artefact:** the command and its output, per claim — the sketch's `EXECUTED (inputs: …)` marker in §2.
2. **Blind partition.** *Which kinds of input never met this claim?* List every way data reaches the changed line and every shape a result takes leaving it, boring ones included — an empty field, another source, an unexpected place (a nested, quoted or escaped context; another field) — derived from the path the data travels and the boundaries it crosses.

   Name the factors the line depends on — input kind, each setting the code reads, the environment property a setting describes (including a value carried from another host), the caller, the next read — and cover every pair of their values with hostile inputs, contradictory pairs included; a pruned pair goes to the attack lane, never only a reason.

   A container kind needs a one-item and a many-item row; a path argument, a row per way it fails: missing, a directory, unreadable, undecodable.

   A predicate that classifies its input (accepted / refused, healthy / unhealthy) runs over the healthy population on the base — every fixture, every stand-in, the sweep — counting its false positives before the freeze.

   A sweep is generated from an enumeration named in the table (source path, member count, members hit), taken where input forms differ — a parser's rules, not its output types; a format's structural tokens and whitespace; a schema's enum values; every writer of the field — never hand-picked; so is every value the changed code writes into or matches against its input's channel (sentinels, placeholders, delimiters, escapes), whole, truncated and joined to a real one.

   A rule that decides one unit of a sequence (a line, a block, a token, a call) is enumerated over every sequence of unit kinds to length 3 at least, each unit's enclosing context varied alone, before trusting a sampled fuzz over the same alphabet.

   **Artefact:** the §2 Partition table; a row that could not be run, or that a sweep never hit, reads `NOT RUN (why)`.
3. **Weak oracle.** *Is the check as strong as the sentence?* Quote the comparison you ran, never a paraphrase. A claim holding a class word — any, every, all, always, never, none, nothing, beyond, unchanged — names the §7 line or `enumerate:` row that searched for its counterexample. A sweep's oracle is a per-field diff against the base — every value the sketch drops, changes or adds — never a pattern for what damage looks like; for each output the change adds or bounds, the sweep prints its observed range beside the stated bound or §3 claim; a value outside it is a finding even when every assertion passed; a differing record is classified by the oracle its attack line names, never by the expected reading. Every rule — every conjunct, metric and sub-check it reads — has a FAIL reading (an equality of counts needs a non-zero precondition: 0 == 0 evaluates nothing): the nearest plausible wrong fix, or the unfixed base on the same data — never an absurd mutant, never a stub. An oracle that executes a component the change depends on cannot grade what that component decides: name an independent one (another implementation, the spec's examples as written, a relation between two runs) or read `NOT RUN (no independent oracle)`. **Artefact:** the PASS and FAIL readings, side by side, in the rule's §5 row.
4. **Blind dataset.** *Could this data show the failure at all?* If the nearest wrong fix also reads PASS, the rule has no power on this dataset: say which slice binds, or delete the rule and list its binding test — a stand-in is yours to build, but adding a dataset to a gate is a ruling. The dataset is reachable from a fresh worktree of the base: committed, or generated by a committed command and seed. **Artefact:** the wrong fix's reading on the same data.
5. **Unfollowed state.** *What happens next?* When a probe leaves something behind — a stored value, a file, a log line — follow it through the next read, write and start before naming its impact in plan step 3's (d) words. When the change writes, state what a repeated write should do and run every input through it twice: a rewrite's second pass changes nothing (f(f(x)) == f(x)); an append is refused, collapsed by its key, or recorded twice by design; when it adds a status or a derived field, read that field after the next write through the public API, not only after the next start. **Artefact:** the three follow-ups, the second-pass and post-write readings — or, if nothing is left behind, the check showing it.

A finding that fits none of the five goes in the lessons file.
