# Cost probes — read at plan step 2 when the diff adds or changes a repeat over input

Whenever the diff adds or changes a repeat over input — a regex quantifier, a loop over user-sized data, a recursion, a call handing user-sized input to a library: every cost probe runs in a subprocess under wall-clock and memory caps at geometric sizes, on one accepted input, one rejected only after the most work possible (a long valid prefix, the deepest nesting, the widest fan-out), and one at each limit the called code declares, each input dimension (count, bytes) grown alone and two at once. It reads CPU time — the clock named with its documented scope, process or thread — and peak memory, head against base on the same input, through the caller's entry point, with every pass it runs; a ratio to any other control is not a cost reading. The brief states the bound; FAIL is the smallest size past it. A DEFAULT that accepts a cost cites both readings. A committed cost test asserts a count of work where the code exposes one, else a ratio of sizes (4n against n, best of k, its margin beside it); its absolute timeout is a hang guard, never the claim.
