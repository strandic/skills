# run <ticket>

Precondition: the brief is where the house rules put plans and the ticket says awaiting go, not shelved.

1. **Wave 0.** Branch and worktree per house rules, with everything the suite needs installed; ticket → in progress. If `git diff --name-only <frozen base> HEAD` touches a file the sketch or §4 names, re-run the sketch's reds on the new base and record it as §9's first row: `W0 | <date> | default | base | <frozen base> → <run base> | <that diff's pasted output ∩ the sketch and §4 files, or none> · <the reds re-run, or not needed>`.
2. **Wave 1**, per the wave rules. An implementer lane's prompt confines it to the worktree and its files, names the test, lint and file-check commands that define done, lets it read the base only through `git show`, never touch the index, and makes it report the tests failing before and after and any blocker outside its files — stop, never fix it.
3. **Wave 2, integrate.** Full suite and lint, passed AND skipped against the base, same toolchain, each run's results in the reports folder, every failure named: a new skip or failure is a finding. Commit per house rules.
4. **Wave 3, review.** Label every finding APPLY, DECLINE, TICKET or RULING (a RULING row goes in the PR's Decisions table); a DECLINE adds one reason: `unreachable` · `pre-existing` · `out-of-scope` · `style` · `superseded` · `false-positive`; an executed all-clear is verification, not a row. An applied behaviour change ships regression tests built from the reviewer's reproduction — one per argument and per read, decode or parse taking the finding's kind of input — shown red on the pre-fix source; each review-round commit names its author. A behaviour-changing review-round commit gets a fresh review lane before the gate, prompted with the pre-fix and fix commits and the finding's reproduction, never the fix's rationale; the lane lists every call site of a changed symbol across the tree, and its all-clear counts only with executed readings. A third round is a RULING.
5. **Stop for a RULING** whenever a change would edit a numbered ruling, a line of §3 or §8 or a line a §3 row points at, or a gate rule or command — one that read FAIL, could not run, or passed but is wrong — and for any finding in a plan-step-3 (c)/(d) class. Any other §2 amendment is a DEFAULT: red-first regression test, a §9 row marked `default`, listed in the next stop message. Record each ruling in §9 and put amended text in later lane prompts; nothing above §9 is edited after `run`, hygiene aside, and observations never go in the brief. Before committing a review round, paste `git diff <pre-round>..<round> -- <files §3 names>`: one RULING stop per round carries every hunk touching a §3 or §8 line or a labelled sketch line, each as was → now, prose-only hunks grouped apart from behaviour hunks; an empty list needs no stop. A pre-existing finding leaving every §3 line and §5 rule true is a TICKET: a (c)/(d) one still stops the run, but the stop offers no fold unless the Siblings rule holds; a fold restarts the review wave.
6. **Wave 4, gate and PR.** The live-data run on the final commit — each §5 rule by its own command line, on the tools committed there, read per its settle clause; a scratch copy, an altered flag or a second reading after a non-PASS is a RULING stop, recorded in §9 even when granted; a later code commit voids the run. PR body: a first line linking the plan ending (trivial note or brief commit) — none, no PR · tickets, brief path · **What** · **Verification** — suite and lint against the base, each §5 rule and each lane reading, taken on the PR head · **Unreviewed since the last lane** — the pasted output of `git log <last reviewed>..HEAD -- <source paths>`, then `empty` or one RULING row per entry; a PR without it is not opened · two tables, written only here, each under its fixed key and dropped when empty: **Decisions** (decision · label · what was done · why), keyed "**RULING:** the ticket owner decided before the work went on. **DEFAULT:** recommended and shown to the ticket owner, and it stood because they didn't strike it."; **Findings** (finding · label · what was done · why), keyed "**APPLY:** fixed in this PR. **DECLINE:** looked at and deliberately not acted on, with the reason. **TICKET:** real, but tracked in its own ticket. Every finding has a row, ruled ones too, tagged (plan) or (review)."; Why gives the reason only; every row reads without the ticket or the brief, an id defined elsewhere only beside a link to its record · **Follow-up**. The stop message and the ticket link those tables and list every DEFAULT row and that field. Ticket per house rules. Stop.

The human merges. Cleanup is a house rule and ends by appending any lessons; every plan ending, run stop, scrap and cleanup appends its own stats line (format per house rules).

## Wave rules (hard)

- **Executed text is committed as it ran.** The brief's executed files (tests and sketch, beside `plan.md`) and a §9 amendment's executed text are committed by the orchestrator, tests first, each commit's diff equal to its text and its subject saying so. What the brief leaves as prose goes to ONE implementer lane.
- **Tests first.** The tests commit, with its edits to existing tests, precedes any code; the orchestrator runs the house rules' file checks on it and diffs the observed red set by name against the predicted one: every *red* reaches its own assertion and fails for the stated reason (a file that cannot load is a finding; stub the new signature where the language needs one), every *guard* is green.
- **A review wave, always.** Reviewers never edit the repo: they patch from a scratch directory and give every finding a minimal runnable reproduction; the orchestrator checks the tree is otherwise unchanged. *Adversarial* when the brief's worst-impact line calls for it — attacks **executed, not reasoned** ([lanes.md](lanes.md)'s 3a row); an all-clear with no observed run does not count. *Code review* otherwise (3b).
- **Orchestrator-only** — git, ticket writes, the spike, the live-data run, the PR. Workers use no real data and no live server.
