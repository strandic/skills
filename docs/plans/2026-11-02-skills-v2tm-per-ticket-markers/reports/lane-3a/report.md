## Findings
- **F1 worktree record injection** through a newline in a path: porcelain without `-z` prints paths raw; `parseWorktrees` splits on `\n\s*\n`; a folder named `a\n\nworktree /X` adds `/X`, whose markers are drawn (current if newer than the start). Repro: `git worktree add --detach "$S/grepo/a\n\nworktree $S/evil"`; kit `A3 parser readings`; real `$S/dump-main2.out`. Spike rule not applied (framing). Fix: `--porcelain -z`; also check `isStdoutTruncated` (> 4 MiB cuts the last record).
- **F2 D5 (a) "never made" does not hold**: newer than the session start is not live — another session's run that crashed after this one started, this session's own run ended without cleanup, a future mtime: each draws undimmed for as long as the marker stays (D2: no cutoff). Repro `A6 crashed sibling run …` (dim false after 1440 checks), `A6 mtime +1 year`. D2 and D5 contradict here.
- **F3 sub-ms boundary**: whole-ms `startedAt`, fractional mtimes, test `at > startedAt` → a marker written in the fraction between `floor(start)` and the true start reads current. Repro `A6 mtime +0.5`. No test uses a fractional mtime.
- **F4 same-mtime rewrite not seen by the 15 s check** (lists only): step stays stale until a tool call or turn end; breaks the README's "within 15 seconds"; the `titles`/`counts` caches keyed by path+mtime keep an old count across tool calls too. Repro `A5 sameMtime,check,*` (16 sequences).
- **F5 bidi controls pass `clean`** (C0, DEL, C1 only): U+202E, U+2066–2069, U+200E/F reach the row. Repro `A1 hostile names` (hasRLO), `A2 bidi step`. Real render: NOT RUN.
- **F6 no cap on W or M**: 1001 worktrees → 1002 ops per tool call, 1001 per check; 4096 markers → 4097 ops, 203 ms, 4096 rows; each marker read whole every pass, up to 4 MiB. No ceiling or FAIL size; cost.md not applied (no capped geometric probe, no CPU/memory per size). Real-fs geometric cost NOT RUN.
- **F7 Q3 per-tool-call bound broken (g1 confirmed)**: after another session changed every plan.md and decisions.md, a tool call costs W+4M (11 vs 9); session start the same. The sketch's Q3 test only measures warm caches (blind dataset). Its name "one marker read" sits beside an assertion of two reads.
- **F8 `walks` cache keeps failures forever** (`.catch(() => null)` stored, never cleared, not at `session.start`): one transient EACCES → the fallback draws nothing for the module's life. Repro `A4 walk cached after a transient failure`.
- **F9 no `timeoutMs` on `process.run`**: a hung `git` holds every `turn.complete` and the first Write/Edit/Bash per new cwd for up to 30 s (real 30058 ms). Repro `A9 never resolves`; `$S/probe.out` last line.
- **F10 Q1 breaks on long rows**: `rowText` cuts the title first, where the ticket is; a long `plan dir not found/not readable` path leaves no ticket; a cut malformed row loses the ticket at the path's end. Repro kit `Q1 plan dir not found, long path, 120 columns` (`hasTicket:false`), `Q1 malformed …`; real `$S/dump-fallback.out` row `un-1`.
